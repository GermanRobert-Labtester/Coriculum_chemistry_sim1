## What this slice is

Every response type needs one defined component: how it renders, what it stores, when it counts as complete, which error states it can show and its full ARIA semantics in Latvian. The registry owns the semantics, the components own the rendering, and this slice owns the join: the payload builder, the single write path through the session machine, the completion overlays the navigator and the review screen read, and the parity proof that the stored payload is what the frozen engines consume.

## The decisions that shaped it

- **The session machine stays the only writer.** `SimInputsIntegration.answer()` builds the payload and dispatches `answer`; it never touches the answer map, and it re-reads the stored payload and compares content digests, so a builder that quietly rewrote a value could not pass unnoticed.
- **Raw is raw.** A numeric answer is stored as the learner typed it — `" 4,70 "` keeps its spaces and its comma — because normalisation belongs to grading. The payload builder validates shape (`raw_string`, `raw_string_map`, `string_list`, `pair_list`) and never converts a value.
- **The vocabulary is frozen and checked.** `data/exam_policy.json` (payload contracts and named variants) and `data/question_schema.json` (payload classes) fix the per-type kind; `data/response_types.json` fixes the variant names. When a registry contract is passed in, the builder refuses a mismatch (`E_INPUTS_CONTRACT_MISMATCH`) instead of drifting.
- **Completion is not computed here.** The verdict belongs to `SimInputsRegistry.completion`; the overlays call it and attach `missing` so the review warning can name the field in Latvian.
- **Q03 is pending, not scored.** The template choice plus the typed fill-ins are stored and `q03PendingPath()` returns `{class: pending, verdict: null, points_awarded: 0}`.

## What N23, N24, N30 and N33 may rely on

- **N23 (grading):** the terminal record carries the raw payloads, and the parity table names the engine and the binding per type. A payload can be handed to its engine as it stands.
- **N24 (form assembly):** `SimInputsIntegration.vocabulary()` is the type → kind/variant map with the ride-along list; `SimInputs.registry.contractFor(typeId)` is the full contract.
- **N30 (practice):** `completionMapState()` and `reviewMissingList()` are pure functions of the map/review state, the answers and the per-slot bindings.
- **N33 (accessibility):** the registry label bank is term-keyed and the render description carries the ARIA names; the live screen-reader pass is N33's.
